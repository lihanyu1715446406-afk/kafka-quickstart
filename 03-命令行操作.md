# 03 命令行操作：把 Kafka 玩起来

这一章全是命令，建议**边看边敲**。所有命令都在 PowerShell 里执行，前提是第 01 章的容器已经启动。

约定：容器名 `kafka`，Kafka 命令目录 `/opt/kafka/bin/`，broker 地址 `localhost:9092`。

---

## 3.0 先认识几个脚本

| 脚本 | 用途 |
|---|---|
| `kafka-topics.sh` | 建/删/改/查 topic |
| `kafka-console-producer.sh` | 命令行发消息 |
| `kafka-console-consumer.sh` | 命令行收消息 |
| `kafka-consumer-groups.sh` | 查消费组、LAG、重置 offset |
| `kafka-configs.sh` | 改 topic / broker 配置 |
| `kafka-get-offsets.sh` | 查分区最新 offset |

> Kafka 4.x 的命令**统一用 `--bootstrap-server`**，不再支持 `--zookeeper`（ZooKeeper 已经被移除）。

每条命令的完整形式都是：

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 ...
```

---

## 3.1 Topic 的增删改查

### 创建 topic

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --create --topic demo-topic --partitions 3 --replication-factor 1
```

参数说明：

- `--partitions 3`：3 个分区；
- `--replication-factor 1`：单机只能 1 个副本。

成功输出：

```
Created topic demo-topic.
```

### 查看所有 topic

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
```

### 查看某个 topic 的详情

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --describe --topic demo-topic
```

输出类似：

```
Topic: demo-topic	TopicId: xxxx	PartitionCount: 3	ReplicationFactor: 1	Configs:
	Topic: demo-topic	Partition: 0	Leader: 1	Replicas: 1	Isr: 1	Elr: 	LastKnownElr:
	Topic: demo-topic	Partition: 1	Leader: 1	Replicas: 1	Isr: 1	Elr: 	LastKnownElr:
	Topic: demo-topic	Partition: 2	Leader: 1	Replicas: 1	Isr: 1	Elr: 	LastKnownElr:
```

- `Leader`：负责这个分区的 broker id（单机就是 1）；
- `Replicas`：副本所在 broker；
- `Isr`：当前同步的副本。

### 增加分区（只能加，不能减）

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --alter --topic demo-topic --partitions 6
```

> 生产环境慎用：分区数变化会影响按 key 的哈希映射，可能破坏"同一 key 顺序消费"的假设。

### 删除 topic

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --delete --topic demo-topic
```

## 3.2 发消息：console producer

打开一个终端，执行：

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-console-producer.sh --bootstrap-server localhost:9092 --topic demo-topic --property parse.key=true --property key.separator=:
```

出现 `>` 提示符后，一行一条消息，格式是 `key:value`：

```
user-1:第一条消息
user-2:第二条消息
user-1:第三条消息
```

按 `Ctrl+C` 退出。

> 不带 `parse.key=true` 时，整行都会当成 value，没有 key。有 key 才能控制分区。

---

## 3.3 收消息：console consumer

### 从最早的消息开始读

新开一个终端：

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic demo-topic --from-beginning --property print.key=true --property print.partition=true --property print.offset=true
```

你应该能看到刚才发的三条消息，并且能看出它们分布在哪些分区、offset 是多少。

输出形如：

```
user-1	0	0	第一条消息
user-2	1	0	第二条消息
user-1	0	1	第三条消息
```

（列依次是 key、partition、offset、value，具体顺序取决于格式化器，重点是观察同一 key 落在同一分区。）

### 带消费组读（会记录 offset）

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic demo-topic --group g1 --property print.key=true --property print.partition=true
```

要点：

- **加了 `--group` 才会提交 offset**，下次再启动会从上次位置继续。
- `--from-beginning` 只在**这个组还没有已提交 offset** 时生效。组一旦有了 offset，就按 offset 继续读。

### 再开一个不同组的消费者

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic demo-topic --group g2 --from-beginning
```

你会看到 **g2 把历史消息又完整读了一遍**——不同消费组互不影响，这就是 Kafka 多订阅者的方式。

### 同一个组开两个消费者

再开一个终端，仍然用 `--group g1`：

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic demo-topic --group g1 --property print.partition=true
```

两个 g1 消费者会各自分到一部分分区（3 个分区分给 2 个人），**同一条消息不会被同组两个人同时消费**。

## 3.4 查看消费组和 LAG

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 --list
```

查看某个组：

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 --describe --group g1
```

输出类似：

```
GROUP  TOPIC       PARTITION  CURRENT-OFFSET  LOG-END-OFFSET  LAG  CONSUMER-ID  HOST  CLIENT-ID
g1     demo-topic  0          2               2               0    ...
g1     demo-topic  1          1               1               0    ...
g1     demo-topic  2          1               1               0    ...
```

三个关键列：

- **CURRENT-OFFSET**：这个组已提交到的位置；
- **LOG-END-OFFSET**：分区当前最新位置（下一条消息的编号）；
- **LAG**：还差多少条没消费 = `LOG-END-OFFSET - CURRENT-OFFSET`。

**LAG 是 Kafka 最重要的监控指标**。LAG 持续上涨，说明消费速度跟不上生产速度。

### 制造一点 LAG 看看

1. 停掉 g1 的所有消费者（Ctrl+C）；
2. 用 console producer 再发 5 条消息；
3. 再执行 `--describe --group g1`，会看到 LAG 变成 5；
4. 重新启动 g1 消费者，消息消费完后 LAG 回到 0。

## 3.5 重置 offset（重放历史消息）

前提：**这个消费组当前没有活跃消费者**，否则会报错。

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 --group g1 --topic demo-topic --reset-offsets --to-earliest --execute
```

常用变体：

```powershell
# 重置到最新（相当于跳过所有积压）
... --reset-offsets --to-latest --execute

# 重置到指定 offset
... --reset-offsets --to-offset 2 --execute

# 从当前位置往回退 3 条
... --reset-offsets --shift-by -3 --execute

# 重置到某个时间点之后
... --reset-offsets --to-datetime 2026-10-29T00:00:00.000 --execute
```

把 `--execute` 换成 `--dry-run` 可以先预览结果，不实际修改。

重置后再启动消费者，就会重新读历史消息——这就是"重放"。

## 3.6 查看分区最新 offset

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-get-offsets.sh --bootstrap-server localhost:9092 --topic demo-topic
```

输出：

```
demo-topic:0:3
demo-topic:1:2
demo-topic:2:1
```

格式是 `topic:partition:最新offset`。可以拿它和消费组的 CURRENT-OFFSET 对照算 LAG。

## 3.7 修改 topic 配置

比如把保留时间改成 1 小时：

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-configs.sh --bootstrap-server localhost:9092 --alter --entity-type topics --entity-name demo-topic --add-config retention.ms=3600000
```

查看当前覆盖的配置：

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-configs.sh --bootstrap-server localhost:9092 --describe --entity-type topics --entity-name demo-topic
```

删除这个覆盖，恢复默认：

```powershell
docker exec -it kafka /opt/kafka/bin/kafka-configs.sh --bootstrap-server localhost:9092 --alter --entity-type topics --entity-name demo-topic --delete-config retention.ms
```

## 3.8 完整练习（建议按顺序做一遍）

```powershell
# 1. 建一个 3 分区 topic
docker exec -it kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --create --topic practice --partitions 3 --replication-factor 1

# 2. 发 6 条带 key 的消息（进入交互模式后逐行输入，Ctrl+C 退出）
docker exec -it kafka /opt/kafka/bin/kafka-console-producer.sh --bootstrap-server localhost:9092 --topic practice --property parse.key=true --property key.separator=:
# user-1:下单
# user-2:下单
# user-1:支付
# user-3:下单
# user-2:支付
# user-1:发货

# 3. 用 g1 组从头消费，观察 key、partition、offset
docker exec -it kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic practice --group g1 --from-beginning --property print.key=true --property print.partition=true --property print.offset=true

# 4. Ctrl+C 停掉，再发 3 条消息，然后看 LAG
docker exec -it kafka /opt/kafka/bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 --describe --group g1

# 5. 重置到最早，重新消费
docker exec -it kafka /opt/kafka/bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 --group g1 --topic practice --reset-offsets --to-earliest --execute
docker exec -it kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic practice --group g1 --from-beginning
```

做完这五步，你已经掌握了 Kafka 日常 80% 的命令行操作。

## 3.9 命令速查

```powershell
# 建 topic
docker exec -it kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --create --topic <name> --partitions 3 --replication-factor 1
# 列 topic
docker exec -it kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --list
# 看详情
docker exec -it kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --describe --topic <name>
# 删 topic
docker exec -it kafka /opt/kafka/bin/kafka-topics.sh --bootstrap-server localhost:9092 --delete --topic <name>
# 发消息
docker exec -it kafka /opt/kafka/bin/kafka-console-producer.sh --bootstrap-server localhost:9092 --topic <name>
# 收消息
docker exec -it kafka /opt/kafka/bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic <name> --from-beginning
# 看组
docker exec -it kafka /opt/kafka/bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 --describe --group <group>
# 重置 offset
docker exec -it kafka /opt/kafka/bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 --group <group> --topic <name> --reset-offsets --to-earliest --execute
```
